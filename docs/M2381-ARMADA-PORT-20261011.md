## 1. 底盘选型存档（官方 armada-os vs sheng fork）

用户问过"为何不用官方 https://github.com/armada-os/armada/releases/tag/20260926"：

| 轴 | 官方 armada-os 20260926 | sheng v1.2（选用） |
|---|---|---|
| 交付形态 | 整盘 gz（ESP+/boot+btrfs /），UEFI 人群（ROCKNIX ABL/SD 卡） | **单分区裸 ext4 fastboot 件** |
| 更新模型 | bootc/OTA 在役（升级连 ghcr） | 砍掉，重刷=升级（与我们模型一致） |
| 刷写 | UEFI 安装器/整盘 dd | `fastboot flash <分区>` = 我们唯一被允许的动作 |
| 调试件 | 无（裸态） | sshd+gadget+steam-now+SELinux permissive 已烤 |

官方版对 m2381 = 解包劈三分区 + btrfs→ext4 + 拆 bootc 双层机器 + 调试件全自建，
收益只有新三周；sheng fork 是官方直系下游（7cf8163 = merge upstream-sync，
Odin/Retroid 设备档案全保留），用户态同源。**官方版留作参照物/备胎**：A/B 若撞
会话层行为差异，可 diff 9/5→9/26 的会话件补丁。用户另手落的
`steamframe-oobe-repair-20260922.5153644-0.3.0.img.bz2`（4.07G）= Frame 冻结线
参照件，收档不动。

## 3. 首启预案（设备日 smoke 清单）

刷写 = `fastboot flash userdata work/meizu-meizu20-armada-r80.img`（只动
userdata，boot_b/ESP/recovery 全不碰；回滚 = 重刷 Debian r78 镜像或 pmOS rootfs，
30 秒锚照旧）。预期链路：ABL → recovery_a ESP v61（EFI stub，cmdline 烤死
root=/dev/sda22）→ armada 容器根 → SDDM autologin `armada`（密码 armada）→
gamescope-session-steam → splash → Steam。

1. 插 USB 线：宿主 `ssh root@172.16.42.1`（NCM gadget，密码 123456 / 或容器侧
   ed25519 key；authorized_keys 若被首启服务抹掉，进去先补）。
2. `journalctl -b` 过一遍：meizu-pas → meizu-touch → meizu-amps → meizu-audio →
   sndcard-bind（card0 出卡，ADSP ~boot+75s 长预算）→ audio-route；
   `aplay -l` 应见 card0。
3. 触摸：meizu-touch 定向绑 a90000（880000 致死定律继续有效，黑名单已随层注入）。
4. 显示：横屏 2400x1080；`journalctl -b | grep -iE "gamescope|rotation"`；若竖屏
   未转 = 档案 `ARMADA_GAMESCOPE_USE_ROTATION_SHADER` 链路问题，回 iancase:
   确认 device-env 输出。
5. 手柄（②d 主场验收）：蓝牙连手柄 → `ls /sys/kernel/config/.../uhid` 或
   hidraw 出现 28DE:12F0 deck-uhid → 游戏内控制。
6. 睡眠：电源键短按 = fake-suspend 熄屏（真 s2idle 已被档案钉 fake）；唤醒 =
   再按电源键。
7. NCM 之外的坑：WiFi 首连走 Steam 设置面板（NM 直连，wpa_supplicant 后端）。
8. 已知噪音（不拦路）：sssd/mdmonitor/nfs-client 等 Fedora 默认件无配置自启
   失败；scx 若报 sched_ext 不支持为装饰性失败。
