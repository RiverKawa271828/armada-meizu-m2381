## 1. 底盘选型存档（官方 armada-os vs sheng fork）

用户问过"为何不用官方 https://github.com/armada-os/armada/releases/tag/20260926"：

| 轴 | 官方 armada-os 20260926 | sheng v1.2（选用） |
|---|---|---|
| 交付形态 | 整盘 gz（ESP+/boot+btrfs /），UEFI 人群（ROCKNIX ABL/SD 卡） | **单分区裸 ext4 fastboot 件** |
| 更新模型 | bootc/OTA 在役（升级连 ghcr） | 砍掉，重刷=升级（与我们模型一致） |
| 刷写 | UEFI 安装器/整盘 dd | `fastboot flash <分区>` = 我们唯一被允许的动作 |
| 调试件 | 无（裸态） | sshd+gadget+steam-now+SELinux permissive 已烤 |

官方版对 m2381 = 解包劈三分区 + btrfs→ext4 + 拆 bootc 双层机器 + 调试件全自建，
收益只有新三周；sheng fork 是官方直系下游（7cf8163 = merge upstream-sync，
Odin/Retroid 设备档案全保留），用户态同源。**官方版留作参照物/备胎**：A/B 若撞
会话层行为差异，可 diff 9/5→9/26 的会话件补丁。用户另手落的
`steamframe-oobe-repair-20260922.5153644-0.3.0.img.bz2`（4.07G）= Frame 冻结线
参照件，收档不动。

## 4. 首启结果（2026-10-11 凌晨，实机）

刷写 = 设备 SSH `reboot bootloader`（10s 进 fastboot，无需拆机按键）→
`fastboot flash userdata` 17 sparse 块全 OKAY，6m08s → `fastboot reboot`。
首启 <1min SSH 可达（NCM gadget + usb0-ip 直接活了）。

**一把通**：growfs 首启长满 457G ✓；SDDM autologin armada ✓；steam
`-gamepadui -steamos3 -steampal -steamdeck` 四旗标在跑（预种客户端直接复用，
~/.local/share/Steam）✓；meizu 全链 active（pas/touch/amps/audio/sndcard-bind/
audio-route）✓；card0 MEIZU20 出卡 ✓；触摸 Goodix Berlin ✓；device-env 全对
（meizu-meizu20 / fake / right / IRQ_CORES=3-7）✓；/dev/uhid 在位 + InputPlumber
active ✓；armada-powerd + suspend-dispatch（fake suspend）接线 ✓；gamescope
3.16.19-257 起、DRM connected=1 ✓；终态 `systemctl --failed` = 0。

**首启抓虫（已修，同步回写适配脚本）**：
1. **FEX x86 腿挂了**：armada-guestos mount 报 "Filesystem uses zstd" —— r80
   内核 CONFIG_SQUASHFS_ZSTD 未开（squashfs 内建仅 zlib）。修法 = 设备侧
   unsquashfs → mksquashfs -comp gzip 原位替换（ArchLinux.sqsh 1.3G + Mesa
   7MB），Mesa 件补 `user.component=fex-mesa` xattr（打在 sqsh 文件本体，FEX
   拿它分类组件）。修后 guestos active + /run/armada/guestos/{rootfs,mesa} 双挂
   ✓。**内核诉求（给 nura 下轮）：CONFIG_SQUASHFS_ZSTD=y**。
2. **PipeWire 只见 Dummy Output**：声卡 boot+75s 迟到，wireplumber 起早没扫到
   ——重启 pipewire/wireplumber 即见 "Built-in Audio Stereo"。固化 =
   `meizu-audio-wireplumber-kick.service`（After=meizu-audio-route，user 级
   try-restart），设备已装 + 适配脚本已带。
3. **armada-controller-type 必炸**：它走 InputPlumber CompositeDevice D-Bus
   apply——m2381 无内置手柄 ⇒ 开机无 CompositeDevice。mask 掉（默认目标本来就
   是 deck-uhid），接手柄后 `controller-type apply` 手动选。
4. **bootc-generic-growpart 失败** = bootc 残件（growfs 接管扩容），mask。
5. **plugin_loader（Decky）连炸** = 首启 exit-code 循环，disable（要插件再
   unmask 装配）。
6. **os-release 还是 Fedora 44**：52-configure-os-release 的产物没在容器导出
   路径上活下来；已按上游格式重写（ID=armada，/etc 软链同源）。
