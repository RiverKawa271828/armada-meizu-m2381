## 1. 底盘选型存档（官方 armada-os vs sheng fork）

用户问过"为何不用官方 https://github.com/armada-os/armada/releases/tag/20260926"：

| 轴 | 官方 armada-os 20260926 | sheng v1.2（选用） |
|---|---|---|
| 交付形态 | 整盘 gz（ESP+/boot+btrfs /），UEFI 人群（ROCKNIX ABL/SD 卡） | **单分区裸 ext4 fastboot 件** |
| 更新模型 | bootc/OTA 在役（升级连 ghcr） | 砍掉，重刷=升级（与我们模型一致） |
| 刷写 | UEFI 安装器/整盘 dd | `fastboot flash <分区>` = 我们唯一被允许的动作 |
| 调试件 | 无（裸态） | sshd+gadget+steam-now+SELinux permissive 已烤 |

Odin/Retroid 设备档案全保留），用户态同源。**官方版留作参照物/备胎**：A/B 若撞
会话层行为差异，可 diff 9/5→9/26 的会话件补丁。用户另手落的
`steamframe-oobe-repair-20260922.5153644-0.3.0.img.bz2`（4.07G）= Frame 冻结线
参照件，收档不动。

3.16.19-257 起、DRM connected=1 ✓；终态 `systemctl --failed` = 0。

**首启抓虫（已修，同步回写适配脚本）**：
1. **FEX x86 腿挂了**：armada-guestos mount 报 "Filesystem uses zstd" —— r80
   内核 CONFIG_SQUASHFS_ZSTD 未开（squashfs 内建仅 zlib）。修法 = 设备侧
   unsquashfs → mksquashfs -comp gzip 原位替换（ArchLinux.sqsh 1.3G + Mesa
   7MB），Mesa 件补 `user.component=fex-mesa` xattr（打在 sqsh 文件本体，FEX
   拿它分类组件）。修后 guestos active + /run/armada/guestos/{rootfs,mesa} 双挂
   ✓。**内核诉求（给 nura 下轮）：CONFIG_SQUASHFS_ZSTD=y**。
2. **PipeWire 只见 Dummy Output**：声卡 boot+75s 迟到，wireplumber 起早没扫到
   ——重启 pipewire/wireplumber 即见 "Built-in Audio Stereo"。固化 =
   `meizu-audio-wireplumber-kick.service`（After=meizu-audio-route，user 级
   try-restart），设备已装 + 适配脚本已带。
3. **armada-controller-type 必炸**：它走 InputPlumber CompositeDevice D-Bus
   apply——m2381 无内置手柄 ⇒ 开机无 CompositeDevice。mask 掉（默认目标本来就
   是 deck-uhid），接手柄后 `controller-type apply` 手动选。
4. **bootc-generic-growpart 失败** = bootc 残件（growfs 接管扩容），mask。
5. **plugin_loader（Decky）连炸** = 首启 exit-code 循环，disable（要插件再
   unmask 装配）。
6. **os-release 还是 Fedora 44**：52-configure-os-release 的产物没在容器导出
   路径上活下来；已按上游格式重写（ID=armada，/etc 软链同源）。
7. **无 RTC 电池首启时钟错乱 → steam bootstrap TLS 全挂**（用户报"无法下载
   所需更新"）：时钟从盘内烤的 2026-07-25 起步，bootstrap 对 CDN 的请求 http
   error 0；chrony 连网后拨正但弹窗不自动重跑。三件套修法（实机已装）：
   **rtc1（pm8xxx PMIC RTC，走电计时）持久化**——开机 `sm20-rtc1-restore`
   （sysinit 早期 hwclock --hctosys，年份 <2026 废值门禁跳过）+ `sm20-rtc1-
   save.timer` 每小时 systohc 写回 + `systemd-time-wait-sync`（TimeoutStartSec
   =25s 兜底，离线开机最多拖 25s 不卡死）。
8. **电源键睡眠假死（黑屏可唤菜单）——本次移植最大抓虫，根因在自己**：
   层里 Debian 时代两份 sleepmask tmpfiles（`meizu-sleepmask.conf`/
   `sm20-sleepmask.conf`）usr 侧 rsync 忘排除 → 首启 systemd-tmpfiles 把
   sleep/suspend/hybrid/suspend-then-hibernate 四个 target 全软链 /dev/null →
   **logind Suspend 永远 Access denied（mask 引发的 EACCES，与 polkit 无关）**
   → steam `Issuing Suspend Command`（systemmanager.txt 07:28:03）石沉大海 →
   steam 停在自己"睡眠黑屏"渲染态等永远不会来的暂停完成，合成器活着（黑底可
   唤菜单）。fake-suspend 全程没得到出场机会。修法 = 清四份掩码 + 删源头
   tmpfiles + **usr 侧 rsync 加 basename 排除（重建同构）**。修后实测全链：
   `systemctl suspend` → `entering fake suspend → display off (gamescope) →
   waiting for wake (pmic_pwrkey) → wake (power key) → leaving fake suspend →
   display on (gamescope)`，steam 经 logind PrepareForSleep 信号正常完成睡眠
   生命周期，电源键睡眠/唤醒 = 原版 Deck 体验。旁证：面板亮屏能力早在（第一
   次唤醒时屏保闪现）。保留上游烤入的 hibernate 系屏蔽（本就无休眠支持）。

## 8. 待机功耗轮（2026-10-11 午，gpu-idle-damp 落地）

**现象**：Steam UI 晾着不碰，机身 44-47°C。计量（qcom-battmgr-usb V×I，满电+USB）：
pre-fix idle 均值 3.85W；GPU 档位驻留 475MHz 39% + 680MHz 42%（simple_ondemand 被
120Hz 合成喂着，不下来）；webhelper 双 renderer 阵发 3 核爆发（瞬时 205%+92%，
占空比 ~37%），爆发把 GPU 顶满档、USB 7.5W 不够用倒贴电池。

**修复 = gpu-idle-damp（用户态三态机）**：无游戏（/proc 容器标记
pressure-vessel/SteamLinuxRuntime/steamapps，括号防自匹配）+ 无输入（evdev 直读
/dev/input/event* 并行 cat，90s 窗）→ 钳 `max_freq=220`；有输入/有游戏 → 放开
680。与 gpu-ondemand-watch 协同：idle 立 /run 旗标，watch 见旗标让路（idle 冻结
是本意，勿当钉死病重绑）。RT 属性：游戏态 8s 内弹满档；标记消失即回钳。

**实测**：idle→220（86s）→ 标记→680（8s）→ 回 220（10s）全链 ✓；post-fix idle
均值 3.08W（静默段 1.7-1.9W 达标，爆发段 4.5-6.8W 是 webhelper CPU 项，GPU 项
已钳死）；温度 47→44.6°C 回落中（长 soak 待观察）。

**结论与路线**：GPU 频率是第一杠杆（220 档 ≈1.7-2.2W，475 档 ≈4.4W）已收；
剩余 = webhelper 阵发 CPU 爆发的触发源（疑似相册屏保预载/通知/商店轮询，需
长观察窗 + DevTools 8080 关联，下轮）。已证伪：`debug_set_fps_limit 60` 对
爆发无效（205→226→210%，非 vsync 驱动）。根因层：governor 钉高档 = msm devfreq
