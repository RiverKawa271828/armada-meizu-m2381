**二、新内核诉求：CONFIG_SQUASHFS_ZSTD=y**

新战线 armada-sheng（Fedora 底 rootfs）的 FEX x86 兼容腿要内核挂载 zstd squashfs
（/usr/share/fex-emu/RootFS/ArchLinux.sqsh），r80 只有 CONFIG_SQUASHFS_ZLIB=y →
挂载必败（实测 "Filesystem uses zstd. This is not supported"）。现 workaround =
设备上 unsquashfs → mksquashfs -comp gzip 原位重压（已验证可用），能出 ZSTD=y 就
免掉这层运行时开销。顺带建议 CONFIG_SQUASHFS_XZ 一并开（上游生态常见压缩）。

**三、两条内核侧情报（供内核线参考）**

1. **GMU/IRQ 亲和性**：armada 的 SM8550 设备档案默认 ARMADA_IRQ_CORES=3-7，注释
   原文 "The A740 GMU wedges if a GPU interrupt wakes CPU 0-2 out of power
   collapse"——与我们 gpu devfreq simple_ondemand 重载卡死 / adreno_gmu 0x8a1
   底噪病史吻合。内核侧若能从 GPU irq affinity 或 devfreq busy 统计根治，我们
   即可撤 gpu-ondemand-watch 看护。
2. **RTC 布局确认**：rtc0 = rtc-efi（读 EIO 废件）、**rtc1 = pm8xxx PMIC RTC
   走电计时正常**——已用 rtc1 做开机 hctosys + 每小时 systohc 持久化（治无 RTC
   电池首启时钟错乱，steam bootstrap TLS 全挂那个坑）。pmOS 线若做 hctosys，
   目标应选 rtc1；顺带可查内核 CONFIG_RTC_HCTOSYS 是否钉在 rtc0（废件）上。
