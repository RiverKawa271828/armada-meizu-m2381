## 0. 结论速览

**建议：Frame 官方底包线复活，先做「零刷机考据」再做 A/B 刷机对照。**
理由一句话：当前卡死的墙（gamescope-control 绑定 → 手柄路由/QAM 往返/菜单黑屏）
**恰好住在 Valve 会话层**——这正是 Debian 线没有、Frame 底包原装的东西；而我们
今晚用 strings 考古 + DMI 伪造手工复刻它的尝试已到边际收益递减点。

## 1. 今晚新增的关键变量（10-09 换轨时不存在的信息）

1. **绑定门禁在 Valve 会话层**：ARM steamui 自带完整 gamescope 协议栈
   （gamescope-control/action-binding-manager/StateChanged），但 "binding
   gamescope-control" 在我们四种会话配置下从不打印。VARIANT_ID=steamdeck +
   DMI Jupiter 伪造只点着了 jupiter 外围命令，握手本体仍哑。**缺的就是 Valve
   官方 start-gamescope-session 传递的某个 env/旗标/文件**——在 Frame 底包里
   这一切是现成的。
2. **游戏内 QAM 面板渲染过一次**（v7 三合一 + wayland）= 渲染腿能通，只差握手。
   问题面从「UI 画不出来」收敛为「握手缺一件」——比换轨时（连 gamescope 点火
   都没成）的问题面小了一个数量级。
3. **同 SoC 双先例**：sheng v0.3.0（小米平板 6S Pro，SM8550，Frame 底包）+
   MaSieS4Fun/SteamOS-ARM-SM8550。修法清单公开（sheng commit ad1d9bc/be14f80）：
   VARIANT_ID=vr→steamdeck、无线后端钉 wpa_supplicant、gamescope 解耦 SteamVR、
   openvr 后端改 drm、SteamVR 屏蔽、jupiter-dock 桩、dbus activation/setuid 修、
   **Steam 窗口 STEAM_GAME atom 焦点补丁**（注意：他们连焦点都打过补丁——
   官方底包≠零坑，但坑是有答案的坑）。
4. **内核腿已 base 无关**：m2381 层 287M（内核模块/固件/设备服务）普通文件
   cp 注入，r79+/v60 腿在两种 rootfs 上通用；音频出声、触屏、BT、NCM 已在
   Debian 线验证，翻译件清单在案（10-08 评估 §2 复用映射表仍然有效）。

## 2. 两条路线的账（2026-10-10 时点）

| 轴 | Debian 13（现役） | Frame 官方底包（初代线，git 可考） |
|---|---|---|
| 游戏/Proton/FEX | ✅ 已通（GRIS/Ori/神渎2 装上即跑） | 同栈（同一 ARM 客户端+Proton ARM），sheng 背书 |
| 渲染/内核腿 | ✅ #80 async flip 原生 | 同一内核腿直挂（无 initramfs 同构） |
| **会话/集成层** | ❌ 手搓会话件 v4→v7，绑定门禁未破 | **Valve 原装 start-gamescope-session + gamescope + steamos-manager + jupiter helpers** |
| 基础设施 | ✅ 已建：音频编排/触屏/NCM/看护/切换器 | 需重移植（systemd 件直移为主，量中等） |
| 包管理 | apt + USTC（快） | pacman + Valve/ALARM 源（CN 速度未知；底包分片 GitHub 可拼） |
| 坑的形态 | 坑无答案，全靠 strings 考古 | 坑有答案（sheng/MaSieS4Fun 修法清单 + Valve 自己的脚本可 diff） |
| 换轨成本 | 0（现役） | P0 1-2 宿主日（管线 git 复活 + sheng 修法移植）+ P1 半个设备日 |

**已方资产双向通用**：steam-client-full.tar.zst 播种（纯文件树）、内核/固件层、
回滚锚（pmOS rootfs 30 秒）、50-restore 设备侧恢复。

## 3. 当时换轨的真实案由（2026-10-10 深夜用户口供补录）

10-09 弃 holo 的原因 = **官方镜像调试入口近乎为零 + 无操作面板**：首次刷入后
没有任何远程入口，NCM gadget 通道调通后仍无 IPv4（最后靠 IPv6 才进调试）；
WiFi / 音频 / 蓝牙 / 显示器在官方镜像上**均无操作面板**（steamos-manager 等
Valve 栈在非 Frame 硬件上不工作，Plasma/KDE 栈当时也未就位）。
**重评时的对冲事实**（换轨后建成、当时不存在的能力）：
- 调试入口：NCM+ssh+autologin+IPv4 直配已全套固化进 graft，新底包构建即带；
- 操作面板：Deck UI 设置面板走 steam 客户端直连 NM/BlueZ/logind（Debian 线
  实测 WiFi 系统级连上、BT 手柄直连），不依赖 steamos-manager；
- 音频：编排三件（amps/sndcard-bind/audio-route）已探明并验证，翻译件可移植。
即：当时劝退的三座山，两座已被架桥、一座已探明深度——但「第一次上去什么都没有
的体验」是真实成本，A/B 轮新底包必须**构建期即带全套调试件**，不留裸态。

## 4. 建议执行序（下会话，刷机前置考据 = 零风险）

1. **考据轮（零刷机，半天）**：拉 steamframe-repair-latest.img.bz2 解包，只干
   三件事——①抄 Valve 原装 gamescope-session 脚本全文（env/旗标/凭据逐行 diff
   我们的 v7）；②看它给 steam 什么身份（os-release/DMI 期望/哪些文件存在性检查）；
   ③对照 sheng 的 10-graft/修法清单。产出 = 「绑定门禁候选清单」，**有可能直接
   在 Debian 线把绑定救活**（把缺的 env/文件补上就完事，不用换底包）。
2. **若考据轮补不活绑定 → A/B 刷机对照**：复活 Frame 管线（git D 状态可考）+
   sheng 修法移植，出一个 frame-base 镜像，与 Debian 镜像同测三症状（游戏内手柄/
   QAM 往返/菜单黑屏）。刷 userdata 可逆，回滚锚照旧，30 秒退出。
3. **决策树**：Frame 底包三症状全绿 → 主力迁 Frame 线，Debian 线降级为实验场；
   Frame 底包同样死 → 墙在 ARM 客户端本体（Valve 的锅），两边一起等客户端更新
   或走自写守护路线（方向 b），Debian 线保留。
4. **无论选哪边先做**：去 sheng / MaSieS4Fun 仓 issue 区问一句「Game Mode 下
   Proton 游戏手柄路由/QAM 是否正常」——他们已实机跑通 SM8550+Frame 底包，
   一条回复能省我们一轮考据。
